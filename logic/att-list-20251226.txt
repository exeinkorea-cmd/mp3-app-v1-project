1. 개요
================================================================================

AttendanceList 컴포넌트는 웹 CMS의 출석 현황을 실시간으로 표시하고, 
AI 챗봇을 통해 자연어 질문으로 데이터를 필터링/정렬하는 기능을 제공합니다.

주요 기능:
- Firestore 실시간 데이터 수신 (onSnapshot)
- AI 기반 자연어 질문 처리 (Google Gemini API)
- 동적 컬럼 표시/숨김
- 필터링 및 정렬
- 공지사항 통합 표시

if (!isNoticeQuery) {
  // 1. AI 함수 호출
  const result = await askGeminiForAttendance(chatInput.trim());
  
  // 2. 응답 구조 분해
  let {
    columns,        // 표시할 컬럼 배열
    filter,         // 필터 조건 객체
    sortBy: aiSortBy,
    sortOrder: aiSortOrder,
    message,        // 사용자 메시지
  } = result;

  // 3. 이름/회사/팀 검색 감지 및 공지 컬럼 추가
  const searchKeywords = ["이름", "회사", "팀", "소속", "업체"];
  const isSearchQuery =
    searchKeywords.some((keyword) =>
      chatInput.toLowerCase().includes(keyword)
    ) ||
    (filter && (filter.userName || filter.department));

  if (isSearchQuery) {
    if (!columns.includes("noticeTitle")) {
      columns = [...columns, "noticeTitle"];
    }
    if (!columns.includes("noticeConfirmed")) {
      columns = [...columns, "noticeConfirmed"];
    }
  }

  // 4. 상태 업데이트
  setActiveColumns(columns.length > 0 ? columns : Object.keys(ALL_COLUMNS));
  setFilterConditions(filter || {});
  if (aiSortBy) setSortBy(aiSortBy);
  if (aiSortOrder) setSortOrder(aiSortOrder);
  setAiMessage(message || "");
}

    const aValue = a[sortBy];
    const bValue = b[sortBy];

    // Timestamp 타입 처리
    if (aValue instanceof Timestamp && bValue instanceof Timestamp) {
      const aTime = aValue.toMillis();
      const bTime = bValue.toMillis();
      return sortOrder === "asc" ? aTime - bTime : bTime - aTime;
    }

    // 일반 값 비교 (문자열)
    const aStr = aValue?.toString() || "";
    const bStr = bValue?.toString() || "";
    return sortOrder === "asc"

8.2. expandedData (useMemo) - 공지 데이터 확장
--------------------------------------------------------
위치: AttendanceList.tsx (라인 356-384)

목적: noticeHistory 배열을 펼쳐서 각 공지마다 별도 행 생성

처리 로직:
```typescript
const expanded: Array<AuthCheckIn & { noticeItem?: {...} }> = [];

filteredAndSortedData.forEach((checkIn) => {
  if (checkIn.noticeHistory && checkIn.noticeHistory.length > 0) {
    // noticeHistory가 있으면 각 공지마다 행 생성
    checkIn.noticeHistory.forEach((noticeItem) => {
      expanded.push({
        ...checkIn,
        noticeItem,  // 현재 행의 공지 정보
      });
    });
  } else {
    // noticeHistory가 없으면 기존처럼 1행만 추가
    expanded.push(checkIn);
  }
});
```

결과:
- noticeHistory가 있는 사용자: 공지 개수만큼 행 생성
- noticeHistory가 없는 사용자: 1행만 생성

- timestamp/checkOutTime: formatTime() 함수로 시간 포맷팅
- noticeConfirmed: noticeItem이 있으면 noticeItem.confirmed 사용, 
  없으면 checkIn.noticeConfirmed 사용
- noticeTitle: noticeItem.title 사용


10. 변수명과 컬럼명 매핑 관계
================================================================================

10.1. 컬럼 키 → AuthCheckIn 필드 매핑
--------------------------------------------------------
ALL_COLUMNS 정의:
- "userName" → AuthCheckIn.userName
- "phoneNumber" → AuthCheckIn.phoneNumber
- "department" → AuthCheckIn.department
- "timestamp" → AuthCheckIn.timestamp
- "checkOutTime" → AuthCheckIn.checkOutTime
- "highRiskWork" → AuthCheckIn.highRiskWork
- "noticeConfirmed" → AuthCheckIn.noticeConfirmed (deprecated) 
                      또는 noticeHistory[].confirmed
- "noticeTitle" → noticeHistory[].title (가상 컬럼)


10.2. AI 응답 필드 → 컬럼 키 매핑
--------------------------------------------------------
askGeminiForAttendance() 응답:
- columns: string[] → activeColumns 상태에 직접 할당
- filter: Record<string, string> → filterConditions 상태에 할당
  * filter의 키는 AuthCheckIn 필드명과 일치해야 함
  * 예: { "department": "삼성물산" } → AuthCheckIn.department 필터링
- sortBy: string → sortBy 상태에 할당
- sortOrder: "asc" | "desc" → sortOrder 상태에 할당


10.3. 필터 조건 키 → 필터링 로직 매핑
--------------------------------------------------------
filterConditions 객체의 키에 따라 다른 필터링 로직 적용:

1. "noticeTitle":
   - noticeHistory 배열 검색
   - noticeHistory.some((notice) => notice.title.includes(value))

2. "timestamp" 또는 "checkOutTime":
   - 시간 조건 파싱
   - 형식: "before:09:00", "after:09:00", "at:09:00", "09:00-12:00"

3. 기타 필드:
   - 부분 일치 검색 (대소문자 무시)
   - item[key].toString().toLowerCase().includes(value.toLowerCase())

13. 주의사항 및 제약사항
================================================================================

1. noticeTitle은 가상 컬럼
   - AuthCheckIn 타입에 직접 정의되지 않음
   - noticeHistory 배열에서 추출
   - ALL_COLUMNS에서 "noticeTitle" as keyof AuthCheckIn로 타입 단언

2. noticeConfirmed 필드
   - AuthCheckIn.noticeConfirmed는 deprecated
   - 실제 사용: noticeHistory[].confirmed
   - 하위 호환성을 위해 두 가지 모두 처리

3. 시간 필터링 형식
   - AI가 반드시 지정된 형식으로 반환해야 함
   - 형식: "before:09:00", "after:09:00", "at:09:00", "09:00-12:00"
   - 파싱 실패 시 문자열 부분 일치로 폴백

4. 공지 데이터 확장
   - noticeHistory가 있는 사용자는 공지 개수만큼 행 생성
   - 같은 사용자가 여러 행으로 표시될 수 있음
   - key prop: `${checkIn.id}-${noticeItem?.id || "default"}-${index}`

5. 실시간 데이터
   - onSnapshot 사용으로 자동 업데이트
   - 네트워크 오류 시 에러 핸들러에서 처리
   - 구독 해제는 useEffect cleanup에서 처리
