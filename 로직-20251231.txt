## 1. 프로젝트 개요

본 프로젝트는 건설 현장 업무 관리 및 안전 공지 전달을 위한 통합 시스템입니다.
모노레포 구조로 구성되어 있으며, 웹 CMS(관리자), 모바일 앱(근로자), 서버 함수(Firebase Functions)로 구성됩니다.

### 기술 스택
- **웹 CMS**: React 19, TypeScript 5, Firebase SDK
- **모바일 앱**: Expo 52, React Native 0.76, TypeScript 5
- **서버**: Firebase Cloud Functions (Node.js, TypeScript)
- **데이터베이스**: Cloud Firestore
- **인증**: Firebase Authentication (익명 인증)
- **스토리지**: Firebase Storage (출석 데이터 백업용)
- **호스팅**: Firebase Hosting (웹 CMS)

### 2.2 packages/functions (Firebase Cloud Functions)

**목적**: 서버 사이드 비즈니스 로직 처리

**주요 기능**:

#### 2.2.1 번역 기능
- `testTranslateV2`: Google Cloud Translate API를 사용한 텍스트 번역
  - 대상 언어: 영어(en), 중국어(zh), 러시아어(ru), 베트남어(vi)
  - CORS 지원

#### 2.2.2 데이터 초기화 및 관리

**일일 자동 초기화** (`dailyResetAt1AM`):
- 실행 시간: 매일 새벽 1시 (한국시간, UTC+9)
- 기능:
  1. authCheckIns 컬렉션 전체 삭제 (출석 데이터 초기화)
  2. bulletins 컬렉션 조건부 삭제:
     - isPersistent=true인 공지는 보존
     - emergencyAlertId가 있는 화재 공지는 삭제
     - isWeatherAlert=true인 날씨 경고는 삭제
  3. 전체 삭제 컬렉션: emergencyAlerts, checkoutPrompts, siteStatusLogs, teamRequests

**수동 데이터 초기화** (`manualResetData`):
- 웹 CMS에서 관리자가 호출
- 커뮤니케이션 데이터만 삭제 (공지, 알림, 메시지, 요청)
- 보존: isPersistent=true 공지, departments 컬렉션, authCheckIns 컬렉션

**강제 로그아웃** (`manualRevokeSessions`):
- 전체 사용자 퇴근 처리
- authCheckIns의 모든 활성 사용자에 checkOutTime 설정 및 location 삭제
- (기존 방식: 문서 삭제 → 현재 방식: 퇴근 처리로 변경)

**기타 소속 강제 로그아웃** (`manualRevokeOthersSessions`):
- "기타" 소속 사용자만 대상으로 퇴근 처리

**개별 사용자 로그아웃** (`revokeUserSession`):
- 특정 전화번호를 가진 사용자의 퇴근 처리

#### 2.2.3 출석 상태 체크 및 퇴근 확인

**스마트 퇴근 체크** (스케줄 함수):
- `checkAttendanceStatus1630`: 매일 16:30 실행
- `checkAttendanceStatus1700`: 매일 17:00 실행
- `checkAttendanceStatus1730`: 매일 17:30 실행
- `checkAttendanceStatus1800`: 매일 18:00 실행

**로직** (`checkAttendanceStatus` 내부 함수):
1. Firestore에서 현장 설정 가져오기 (settings/site_config)
   - center: 현장 중심 좌표
   - allowedRadiusMeters: 허용 반경 (미터)

2. 활성 사용자 조회 (checkOutTime이 없는 사용자)

3. 각 사용자의 GPS 위치를 현장 중심과 비교 (Haversine 공식)
   - 현장 내부 사용자: siteStatusLogs에 기록
   - 현장 외부 사용자: checkoutPrompts에 퇴근 확인 알림 생성
   - 30분 이상 현장 외부에 있는 사용자: 자동 퇴근 처리 (checkOutTime 설정 + location 삭제)

#### 2.2.4 GPS 확인 및 백업

**전체 근로자 GPS 확인** (`checkAllWorkersGPSAt1PM`):
- 실행 시간: 매일 13:00 (한국시간)
- 활성 사용자의 GPS 위치 확인
- 2시간 이상 업데이트되지 않은 위치 감지
- siteStatusLogs에 결과 기록

**출석 데이터 백업**:
- `backupAttendanceDataAt1050`: 매일 10:50 실행
- `backupAttendanceDataAt1350`: 매일 13:50 실행
- 기능 (`backupAttendanceDataToExcel`):
  1. authCheckIns 컬렉션 데이터 조회
  2. XLSX 라이브러리로 엑셀 파일 생성
  3. Firebase Storage에 업로드
  4. 저장 경로: attendance-backups/attendance_{날짜}_{시간}.xlsx

#### 2.2.5 AI 챗봇 기능

**출석 쿼리 분석** (`analyzeAttendanceQuery`):
- Gemini 2.0 Flash 모델 사용
- 사용자 질문을 분석하여 Firestore 쿼리 파라미터 생성
- 응답 형식:
  ```json
  {
    "columns": ["userName", "department", "timestamp"],
    "filter": { "department": "삼성물산" },
    "sortBy": "timestamp",
    "sortOrder": "desc",
    "message": "삼성물산 직원들의 출근 기록입니다."
  }
  ```
- 시간 필터링 지원: "before:09:00", "after:09:00", "09:00-12:00" 등

**공지 조회 챗봇** (`analyzeNoticeStatusQuery`):
- 이름/회사명/팀명으로 검색하여 공지 내용과 확인 여부 조회
- 마크다운 테이블 형식으로 응답

#### 2.2.6 긴급 알림 처리

**화재 공지 자동 생성** (`onEmergencyAlertCreated`):
- 트리거: emergencyAlerts 컬렉션에 "fire" 타입 문서 생성 시
- 기능:
  - 다국어 긴급 공지사항 생성 (bulletins 컬렉션)
  - emergencyAlertId 필드로 원본 알림과 연결
  - isPersistent=true로 설정하여 상단 고정

#### 2.2.7 날씨 경고 시스템

**날씨 체크 및 경고 발송** (`checkWeatherAndSendAlert`):
- 실행 시간: 매시간 정각
- 로직:
  1. OpenWeatherMap API로 현장 위치의 날씨 데이터 조회
  2. 체감온도(feels_like) 확인
  3. 온도 범위별 경고 메시지 생성:
     - 폭염: ≥38°C (긴급), 35-37°C (경고), 33-34°C (주의), 31-32°C (주의보)
     - 한파: ≤-12°C (주의보), -11~-6°C (관심)
  4. 다국어 번역 포함 (한국어, 영어, 중국어, 베트남어, 러시아어)
  5. 중복 방지: 오늘 이미 같은 경고를 발송했으면 건너뜀
  6. bulletins 컬렉션에 isWeatherAlert=true로 저장

### 2.4 packages/mobiles (모바일 앱)

**목적**: 현장 근로자가 출근, 공지 확인, 긴급 알림 신고 등을 수행하는 모바일 애플리케이션

**주요 기능**:

#### 2.4.1 로그인 및 출근 처리

**SignInForm 컴포넌트**:
1. 사용자 정보 입력:
   - 이름, 전화번호
   - 소속 선택 (회사 → 팀)
   - "기타" 옵션 지원 (teamRequests에 요청 생성)

2. GPS 권한 요청 및 위치 확인:
   - expo-location으로 현재 위치 조회
   - 현장 설정(settings/site_config)과 비교하여 반경 체크
   - 범위 밖이면 로그인 차단

3. Firebase Auth 익명 로그인

4. 출석 데이터 생성 (authCheckIns 컬렉션):
   - phoneNumber, userName, department
   - timestamp (서버 타임스탬프)
   - location (GPS 좌표)
   - highRiskWork (고위험작업 제목, 기기 언어 설정 기반)

5. 입력 정보 저장 (AsyncStorage):
   - @mobile_user: 현재 로그인된 사용자 정보
   - @remembered_user_inputs: 재로그인 시 자동 채우기용

#### 2.4.2 공지사항 확인

**BulletinList 컴포넌트**:
- 실시간 공지사항 조회 (Firestore onSnapshot)
- 다국어 지원 (한국어, 중국어, 베트남어, 러시아어)
- 공지 필터링:
  - targetType="all": 모든 사용자
  - targetType="company": 특정 회사만
  - targetType="team": 특정 팀만
- 공지 확인 체크박스:
  - GPS 위치 확인 (현장 반경 체크)
  - authCheckIns의 noticeHistory 업데이트
  - AsyncStorage에 체크 상태 저장
- 새 공지 도착 시 알림 소리 재생:
  - 화재/날씨 경고: fire_alert_sound.wav + 진동
  - 일반 공지: notification_sound.wav

#### 2.4.3 긴급 버튼

**화재 버튼**:
- 119 전화 연결
- 현재 위치와 함께 emergencyAlerts 컬렉션에 "fire" 타입 문서 생성
- 서버 함수에서 자동으로 긴급 공지사항 생성

**요청 버튼** (해피콜):
- 02-2154-9717 전화 연결
- emergencyAlerts 컬렉션에 "happy_call" 타입 문서 생성

**퇴근 버튼**:
- revokeUserSession 서버 함수 호출
- Firebase Auth 로그아웃

#### 2.4.4 자동 로그아웃 감지

**세 가지 방식의 로그아웃 감지**:

1. **토큰 만료 감지** (onIdTokenChanged):
   - 서버에서 토큰이 revoke되면 자동 로그아웃
   - 세션 만료 시 강제 로그아웃

2. **출석 데이터 변경 감지** (onSnapshot):
   - authCheckIns에서 checkOutTime이 설정되면 로그아웃
   - 문서가 삭제되면 로그아웃 (강제 로그아웃)

3. **위치 업데이트**:
   - (향후 구현 가능) 주기적으로 GPS 위치 업데이트

## 3. 데이터베이스 구조 (Firestore)

### 3.1 컬렉션 구조

#### departments (소속 정보)
```typescript
{
  id: string;          // 문서 ID
  name: string;        // 회사명 또는 팀명
  type: "company" | "team";
  parentId?: string;   // 팀의 경우 소속 업체 ID
  createdAt: Timestamp;
}
```
- **접근 규칙**: 모든 사용자 읽기 가능, 인증된 사용자만 쓰기 가능
- **용도**: 로그인 시 소속 선택, 공지사항 대상 선택

#### settings (현장 설정)
```typescript
{
  id: "site_config";   // 고정 문서 ID
  center: {
    latitude: number;
    longitude: number;
  };
  allowedRadiusMeters: number;  // 허용 반경 (미터)
  autoGpsCheckEnabled?: boolean; // GPS 자동 확인 활성화 여부
  autoBackupEnabled?: boolean;   // 자동 백업 활성화 여부
  backupFolderPath?: string;     // 백업 폴더 경로
}
```
- **접근 규칙**: 모든 사용자 읽기 가능, 인증된 사용자만 쓰기 가능
- **용도**: GPS 반경 체크, 스케줄 함수 설정

#### authCheckIns (출석 데이터)
```typescript
{
  id: string;                    // 문서 ID
  phoneNumber: string;           // 사용자 식별용 (필수)
  userName: string;              // 표시용 이름
  department: string;            // "회사명 - 팀명" 형식
  userId?: string;               // Firebase Auth UID
  timestamp: Timestamp;          // 출근 시간 (서버 타임스탬프)
  checkOutTime?: Timestamp;      // 퇴근 시간 (서버 타임스탬프)
  location?: {                   // GPS 위치
    latitude: number;
    longitude: number;
  };
  locationUpdatedAt?: Timestamp; // 위치 업데이트 시간
  highRiskWork?: string;         // 고위험작업 제목
  highRiskWorkUpdatedAt?: Timestamp;
  noticeConfirmed?: boolean;     // (deprecated) 공지 확인 여부
  noticeHistory?: Array<{        // 공지 확인 이력
    id: string;                  // bulletin ID
    title: string;               // 공지 제목
    confirmed: boolean;          // 확인 여부
    sentAt: Timestamp;           // 발송 시간
  }>;
  lastCheckoutPrompt?: {         // 마지막 퇴근 확인 알림
    timestamp: Timestamp;
    checkTime: string;
  };
}
```
- **접근 규칙**: 인증된 사용자만 읽기/쓰기 가능
- **용도**: 출근/퇴근 기록, GPS 추적, 공지 확인 이력
- **인덱스**: phoneNumber, timestamp (복합 인덱스 필요)

#### bulletins (공지사항)
```typescript
{
  id: string;                    // 문서 ID
  title: string;                 // 제목 (한국어)
  originalText: string;          // 내용 (한국어)
  titleTranslations?: Record<string, string>; // 다국어 제목
  contentTranslations?: Record<string, string>; // 다국어 내용
  authorEmail: string;           // 작성자 이메일
  department?: string;           // (하위 호환성) 작성자 소속
  targetType: "all" | "company" | "team"; // 대상 타입
  targetValue?: string | null;   // 단일 대상 ID
  targetValues?: string[];       // 여러 대상 ID 배열
  isPersistent: boolean;         // 지속 공지 여부 (일일 초기화 시 보존)
  expiryDate?: Timestamp;        // 만료일
  createdAt: Timestamp;          // 생성 시간 (서버 타임스탬프)
  createdBy?: string;            // 생성자 (system 또는 사용자)
  status?: string;               // 상태
  isWeatherAlert?: boolean;      // 날씨 경고 여부
  emergencyAlertId?: string;     // 긴급 알림 ID (화재 공지 연결)
  weatherAlertType?: "heat" | "cold"; // 날씨 경고 타입
}
```
- **접근 규칙**: 인증된 사용자만 읽기/쓰기 가능
- **용도**: 안전 공지, 긴급 알림, 날씨 경고 전달
- **인덱스**: createdAt (desc), isWeatherAlert, emergencyAlertId

#### emergencyAlerts (긴급 알림)
```typescript
{
  id: string;                    // 문서 ID
```

## 8. 주요 알고리즘 및 로직

### 8.1 Haversine 공식 (거리 계산)

```typescript
const calculateDistance = (lat1, lon1, lat2, lon2): number => {
  const R = 6371000; // 지구 반경 (미터)
  const dLat = ((lat2 - lat1) * Math.PI) / 180;
  const dLon = ((lon2 - lon1) * Math.PI) / 180;
  const a =
    Math.sin(dLat / 2) * Math.sin(dLat / 2) +
    Math.cos((lat1 * Math.PI) / 180) *
      Math.cos((lat2 * Math.PI) / 180) *
      Math.sin(dLon / 2) *
      Math.sin(dLon / 2);
  const c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
  return R * c; // 미터 단위
};
```

**용도**:
- 로그인 시 현장 반경 체크
- 퇴근 확인 시 현장 내/외부 판별
- 공지 확인 시 현장 반경 체크

### 8.2 배치 처리 로직

**최대 배치 크기**: 400개 (Firestore 제한)

```typescript
const MAX_BATCH_SIZE = 400;
const batches: Promise<any>[] = [];
let batch = db.batch();
let count = 0;

for (const doc of snapshot.docs) {
  batch.delete(doc.ref); // 또는 update, set
  count++;
  if (count >= MAX_BATCH_SIZE) {

    count = 0;

await Promise.all(batches); // 병렬 실행
```

```typescript
  const langCode = languageMap[selectedLanguage];
  if (selectedLanguage === "한국어") {
    return item.originalText;
  }
  return item.contentTranslations?.[langCode] || item.originalText;
};
```

## 10. 성능 최적화

### 10.1 Lazy Loading

**Functions에서**:
- cors: 동적 import (배포 타임아웃 방지)
- GoogleGenerativeAI: 동적 import
- XLSX: 동적 import

**패턴**:
```typescript
let corsHandlerInstance: any | null = null;
function getCorsHandler() {
  if (!corsHandlerInstance) {
    const corsModule = require("cors");
    corsHandlerInstance = corsModule({ ... });
  }
  return corsHandlerInstance;
}
```

### 10.2 Firestore 쿼리 최적화

**인덱스 필수**:
- authCheckIns: phoneNumber + timestamp (복합 인덱스)
- bulletins: createdAt (desc), isWeatherAlert, emergencyAlertId
- emergencyAlerts: type + timestamp (복합 인덱스)

**쿼리 제한**:
- orderBy는 인덱스 필요
- where + orderBy 조합 시 복합 인덱스 필요

### 10.3 실시간 업데이트 최적화

**onSnapshot 사용**:
- 초기 로드 시 모든 문서 처리
- 이후 변경사항만 처리 (docChanges 사용)
- 중복 방지 로직으로 불필요한 처리 방지

**컴포넌트 언마운트 시 정리**:
```typescript
useEffect(() => {
  const unsubscribe = onSnapshot(query, callback);
```
